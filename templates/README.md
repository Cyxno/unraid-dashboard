# Unraid templates

Canonical [Community Applications][ca] Docker templates for Beacon, kept in
the repository so they stay in lockstep with the images they reference.

## The honest architecture

Community Applications (and Unraid's Docker tab templates) install **one
container per XML template** — there is no supported way for a single CA
entry to install and manage the two Beacon containers as one unit. Beacon is
one product shipped as two containers:

| Container | Image | Role |
| --- | --- | --- |
| `unraid-dashboard` | `ghcr.io/cyxno/unraid-dashboard` | the web app — UI, dashboards, API backend |
| `unraid-dashboard-helper` | `ghcr.io/cyxno/unraid-dashboard-helper` | optional verified-update helper — the only component with Docker-socket access |

Therefore:

- **Recommended (one product, one step):** the [docker-compose bundle](../docker-compose.yml).
  On Unraid 7.2+ this is a first-class workflow: **Docker → Compose → Add New
  Stack** and paste the compose file — the same pattern multi-container apps
  such as Immich officially document. Outside Unraid: `git clone`, `cp
  .env.example .env`, `docker compose up -d`.
- **Community Applications:** install the **unraid-dashboard** template for
  the dashboard (updates then flow through Unraid's own Apps-tab update
  mechanism), and optionally the **unraid-dashboard-helper** template for
  verified in-app updates. Note the helper binds `127.0.0.1:8790` only, so it
  pairs with the compose bundle or a host-network dashboard — this
  restriction is deliberate (it is the component that can control Docker).

## Templates

| File | Installs |
| --- | --- |
| `unraid-dashboard.xml` | the dashboard container (bridge network, Web UI on 8090) |
| `unraid-dashboard-helper.xml` | the update helper (host network, localhost-only) |

Both use `<TemplateURL>` pointing at the raw files in this repository, so
"Add Container → from URL" works and any CA listing always tracks this
directory.

## Publishing to Community Applications

The templates follow the current CA conventions (one XML per container,
`raw.githubusercontent.com` TemplateURL, masked secret fields). To get
Beacon listed in the Apps tab:

1. Fork [selfhosters/unRAID-CA-templates][st] (or host the templates in your
   own public repository) and open a PR adding the two XMLs to `templates/`.
2. Keep the icons reachable over HTTPS (the templates reference the raw SVG
   in this repository).
3. After merge, the apps appear in CA under **Tools: Utilities**; the
   `Requires` field on the helper template cross-references the dashboard.

Secrets: no template ships a default credential. The API key and helper
token fields are empty and masked; the helper token is generated by the user
(`openssl rand -hex 32`) and stored only in the container configuration.
